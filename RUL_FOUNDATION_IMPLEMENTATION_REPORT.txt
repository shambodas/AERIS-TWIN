1. IMPLEMENTATION SUMMARY
--------------------------------------------------------------------------------
The AERIS-TWIN simulation engine has been corrected to support mathematically sound, 
physics-based progressive degradation and true End-of-Life (EOL) simulation. 

- Simulation Engine: Modified `EngineSimulator` to compute monotonic wear based strictly 
  on physical variables (RPM and Thermal States). The artificial `LOITER` timer was removed.
  The new wear equation was calibrated using a quadratic scaling to ensure meaningful
  stage progressions across all operating conditions.
- RUL Constraints: Remaining Useful Life (RUL) is monotonically non-increasing within a 
  trajectory and reaches exactly 0.0 at EOL. The RUL label is isolated from the latent 
  degradation variables.
- Operational Profiles: GENTLE, NOMINAL, and HARSH profiles vary solely by 
  altitude, base load, and throttle percentages. The EOL naturally emerges from the 
  wear accumulation dynamics.
- System Integration: `server.py` and the telemetry handlers correctly handle ENGINE_FAILURE.

2. RUN-TO-FAILURE DATASET GENERATION
--------------------------------------------------------------------------------
The script (`data/generate_rul_dataset.py`) produces RUL run-to-failure datasets with 
genuine physical trajectory diversity. Rather than only altering sensor noise, the 
random seed perturbs the latent `wear_rate_multiplier`, base load, altitude, throttle, 
and initial wear. These latent parameters are intentionally omitted from the generated 
features to prevent ground-truth leakage.
