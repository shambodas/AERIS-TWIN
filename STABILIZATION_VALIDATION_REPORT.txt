EXECUTIVE SUMMARY
-----------------

The stabilization pass traced the normal-flight warning through the complete
simulation and intelligence chain. The warning was not caused by the frontend.
There were several backend and model-contract problems:

1. The first telemetry sample used generic 70 percent throttle inputs instead
   of the mission ground operating point.
2. The fallback anomaly detector averaged incompatible raw units such as RPM,
   altitude, and sensor deviations, causing normal values to saturate anomaly
   scoring.
3. Oil-temperature deviations were calculated against a missing field alias,
   effectively comparing measured oil temperature with zero.
4. Severity applied a fixed affected-channel penalty to every sample.
5. The propeller coefficient was capped below the documented calibration
   range, leaving propeller load far below engine torque and causing RPM/EGT
   runaway during normal operation.
6. EGT cooling was scaled by 0.22 even though the simulator's operating range
   required approximately full cooling transfer for stable normal EGT.
7. EGT, CHT, oil temperature, and oil pressure expectation terms did not match
   the simulator's measured normal operating envelope.
8. Fault clearing did not reset temporal intelligence history, delaying
   recovery classification.
9. Persisted ML training used raw CSV columns while runtime inference expected
   engineered features. The first generated model bundle was therefore not
   compatible with runtime inference.

After the expectation, scoring, initialization, and physics calibration fixes,
the validated normal operating matrix produced NORMAL classification, no
anomaly flag, NORMAL severity, and health scores from approximately 87 to 91
after ten seconds of operation.

The ML train/save/load lifecycle now works technically and tests pass. However,
the refreshed models still do not pass live runtime quality validation for all
current scenarios. Therefore the default server runtime intentionally uses the
validated FALLBACK_INTELLIGENCE path. MACHINE_LEARNING requires explicit
AERIS_ENABLE_ML=1 and is not claimed as the default demo intelligence.

ROOT-CAUSE INTERPRETATION
-------------------------

The original normal warning was a chain of independent contract errors rather
than one frontend display mistake.

At the beginning of the audit, a normal simulator sample had approximately:

  CHT:             50 C
  EGT:             55 C
  oil temperature: 50 C
  oil pressure:    86 psi
  vibration:       0.16 RMS

The expectation model predicted values such as CHT 93 C, EGT 106 C, oil
pressure 55 psi, and fuel flow 0.285 kg/s. These mismatches created large
deviations. The oil-temperature field mismatch made the problem worse by
comparing against zero.

The fallback anomaly detector then averaged raw engineering values. RPM near
3,000 dominated the score even when all normalized deviations were small.
Health also subtracted classifier confidence even when the classifier said
NORMAL, and severity added a fixed two-channel penalty.

After those intelligence corrections, long-running normal operation still
showed EGT runaway. Direct physics tracing showed engine torque near 65-88 Nm
while propeller torque was only approximately 3-6 Nm. The coefficient cap made
the documented propeller calibration unreachable. EGT cooling at 22 percent
also allowed thermal accumulation. Correcting those physics constants made
the simulator's normal operating envelope stable enough to calibrate expected
values meaningfully.

KNOWN LIMITATIONS
-----------------

1. The trained ML bundle is technically functional but not yet accepted as the
   default runtime detector because live inference quality is inconsistent.
2. sklearn emits feature-name warnings because inference currently passes lists
   while models are fitted with DataFrames. This does not fail the tests but
   should be cleaned up in a future ML quality pass.
3. The current UI label Oil Pressure maps to the existing simulator misfire
   API because the project does not contain a dedicated oil-pressure fault
   model. The existing supported fault mapping was preserved rather than
   inventing a new backend fault.
4. Sensor drift arbitration is strongest during the early single-channel
   evidence window. Over longer simulated periods, unrelated simulator thermal
   dynamics can add correlated deviations and reduce confidence in the sensor
   diagnosis.
5. Browser automation did not reliably perform a Leaflet map click, although
   backend waypoint, path, and movement behavior passed direct and HTTP tests.
6. The bundled .venv remains unusable because its Python 3.14 target is missing.
   Tests were run successfully using system Python 3.13.7 with requirements
   installed.
7. The dashboard can show a warning at an operator target that is outside the
   validated steady-state matrix, such as the current GCS default of 3,500 m,
   if the simulator has not settled or the operating point differs from the
   calibrated normal cases. This is exposed as intelligence output rather than
   hidden.


FINAL INTERPRETATION
--------------------

The system now has a single backend-owned runtime state for lifecycle,
telemetry, engine status, health, UAV movement, and path state. GCS and the
dashboard are two consumers of that state. Stop and restart are deterministic,
and the dashboard no longer claims live monitoring after the backend stops.

The normal-flight false positive was investigated at the physics and
intelligence layers. It was not hidden with frontend conditions. The corrected
fallback path recognizes the validated normal operating envelope as NORMAL and
produces high health. Fault injection remains distinguishable from normal
operation, and clearing a fault resets temporal history so recovery can be
observed.

The ML lifecycle is now reproducible and test-covered at the persistence level,
but the active model quality gate honestly remains open. The project therefore
does not claim machine-learning detection in the default demo. The dashboard
explicitly identifies validated fallback intelligence, while explicit ML
opt-in remains available for continued model calibration.
