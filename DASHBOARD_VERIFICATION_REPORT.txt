1. SYSTEM OVERVIEW
------------------
STATUS: PASS

The prototype consists of one Python server adapter and two browser routes:

- /gcs: judge-facing UAV ground-control interface.
- /engine: engine and digital-twin monitoring interface.

Both routes connect to one server.py process and one EngineSimulator instance.
The existing Python engine remains the source of truth for engine behavior,
sensors, faults, mission inputs, and measured telemetry.

24. KNOWN LIMITATIONS
---------------------
STATUS: DOCUMENTED

- UAV position follows mission progress along a predefined simulated route.
- No real GPS or flight-dynamics model exists in the adapter.
- Heading is visual/UAV state only, not an engine input.
- Throttle follows MissionProfile; direct runtime throttle is rejected.
- Start sequence has READY and FLYING states only; STARTING/TAKEOFF states are
  not modeled by the existing backend.
- Replay uses the in-memory 600-sample buffer, not historical CSV files.
- MQTT was not live-tested.
- Separate physical LAN devices were not tested.
- Offline simulator restart behavior was not fully tested.
- Health and contributor values are rule-based, not ML output.
- No real hardware sensor data is used.

28. HOW TO RUN
--------------
From the repository root:

  python server.py

Open locally:

  http://localhost:8080/gcs
  http://localhost:8080/engine

For LAN access, use the host machine's LAN address:

  http://<host-lan-ip>:8080/gcs
  http://<host-lan-ip>:8080/engine

The host firewall must allow TCP port 8080. MQTT is optional:

  AERIS_MQTT=1
  AERIS_MQTT_HOST=<broker-host>
  AERIS_MQTT_PORT=1883

29. SIH DEMONSTRATION PROCEDURE
-------------------------------
1. Start server.py.
2. Open /gcs and /engine in separate browser tabs.
3. Select Cruise ISR.
4. Click START MISSION and observe READY -> FLYING.
5. Adjust altitude and verify the map readout changes.
6. Adjust heading and verify the SVG aircraft rotates.
7. Click INJECT OVERHEATING / COOLING while flying.
8. Confirm GCS WARNING and COOLING DEGRADATION.
9. Confirm Engine Monitor fault, alert, telemetry, and health change.
10. Use CLEAR FAULT or RESET SYSTEM and confirm recovery.
11. Load session history on /engine.
12. Use PLAY REPLAY and STOP REPLAY.
13. Use MISSION REPORT to show the telemetry-derived summary.

PARTIALLY WORKING
------------------

- MQTT integration is configured but not live-broker tested.
- Two browser pages were verified; separate physical devices were not tested.
- Offline simulator recovery and long-duration performance were not fully tested.

NOT IMPLEMENTED
---------------
- ML anomaly detection, classification, prediction, confidence, and RUL.
- Real GPS/aircraft flight dynamics.
- Historical CSV replay service.
- MQTT command subscriber.
- Authentication and production security controls.

CRITICAL ISSUES
---------------
- No blocker was found in the tested local demonstration flow.
- A trusted-LAN firewall rule is required for physical second-device access.
- The simulator must be restarted with the current server.py before testing
  newly added endpoints after an older process has been running.
